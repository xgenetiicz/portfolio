# Reflection Note
**Hello dear reader!**


By developing this project, I learned how to interpret every problem
and actually find out on my own as Seniors do - debug and find solutions on their own by searching and reading others' code.
The thing is when you actually find out the solution on your own, you also learn how to adapt other code into your own codebase -
and this is a great way of learning. Because when you first solve the problem, it becomes easier to adapt and solve other problems,
and you interpret problem-solving in a different way, looking at problems from very different aspects.

You have no choice but to actually understand each line of code - which is where every developer should be.
The reason I work this way is that I want to have that desired knowledge that seniors have today, where
they found out the solutions on their own and got excellent at it.

I have never learned so much as I do now, because every time I solve a specific problem
I get that "Aha, it makes so much sense now" moment. This also makes developing really fun, and the learning curve
is huge.

I've come to an understanding that LLMs are a good tool, but that tool is useless for me as a developer if I don't actually
understand the whole output of the code each time. When you cannot trace line by line yourself, you cannot know how to implement features or understand which data structure to use.
It's like driving a manual car but not knowing when or how to switch gears at the right time, and when you don't, the car will stall and stop. In other words, the person cannot develop.

update: 
I learned best by writing code on whiteboard! This was just another level of learning - had no choice but to actual trace objects and pass them into variables in correct order to understand how
I should implement the method. Also the same with nested loops.
